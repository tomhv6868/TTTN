# T8.5 — NIDS runtime liên tục

T8.5 chạy Ubuntu như một passive NIDS sensor lâu dài. Sensor nhận packet từ NIC
DPDK, cập nhật flow, tạo F9, chạy model inference và phát alert. Alert không làm
process dừng. Runtime chỉ dừng bởi `SIGINT`, `SIGTERM` hoặc lỗi pipeline/DPDK
không thể tiếp tục.

Canonical workflow chỉ dùng:

- `scripts/ubuntu_t85_detection.sh`
- `scripts/kali_t85_bulk_replay.sh`

Các scenario/demo script cũ không nằm trên critical path của runtime.

## Topology

- Kali `192.168.252.10`: replay CICIDS2017 và tạo live traffic.
- Windows `192.168.252.20`: victim của live test.
- Ubuntu `ens160`: sensor NIC, bind sang DPDK và chạy promiscuous.
- Ubuntu `ens33`: management NIC, luôn do Linux kernel quản lý.

## Chạy sensor trên Ubuntu

```bash
cd /mnt/hgfs/TTTN
bash scripts/ubuntu_t85_detection.sh
```

Bundle khác mặc định:

```bash
bash scripts/ubuntu_t85_detection.sh \
  --bundle "$HOME/.cache/nids-partial-flow/t5.2/bundles/F9"
```

Launcher build binary, tạo preflight từ `config/dpdk-passive.json`, bind đúng
sensor NIC, bật promiscuous và chạy:

```text
--max-packets 0
--idle-timeout-ms 0
```

Không dùng `--stop-after-alert`. Output JSONL được append vào:

```text
run_log/t8.5/detection.jsonl
```

Nhấn `Ctrl+C` để dừng. Binary thoát RX loop và đóng DPDK port; launcher sau đó
gọi `dpdk_smoke.py rollback` để bind lại driver, MTU, địa chỉ và trạng thái NIC.

## Replay toàn bộ CICIDS2017 trên Kali

Chỉ chạy sau khi Ubuntu phát event `nids_dpdk_live_ready` với
`"continuous":true`.

```bash
cd /mnt/hgfs/TTTN
bash scripts/kali_t85_bulk_replay.sh \
  --interface eth1 \
  --destination-mac 00:0c:29:eb:d8:c4 \
  --pcap-dir /mnt/hgfs/TTTN/pcap \
  --speed 1
```

`--speed` chỉ nhận `1`, `5` hoặc `topspeed`. Dùng `1` cho functional replay,
`5` cho accelerated replay và `topspeed` cho stress/throughput. Script chỉ
rewrite Ethernet source/destination MAC. IP, TCP/UDP port và payload được giữ
nguyên.

Kali data NIC được nâng MTU lên 9000 trong lúc replay và luôn được restore về
MTU ban đầu khi kết thúc hoặc nhận signal. `tcpreplay-edit` output được append
vào:

```text
run_log/t8.5/replay.log
```

Replay fail nếu `tcpreplay-edit` trả lỗi hoặc báo `Failed packets` khác zero.
Khi năm PCAP kết thúc, Kali dừng nhưng Ubuntu sensor tiếp tục chạy.

## Live Kali → Windows

Giữ nguyên process Ubuntu. Chạy từng tool trực tiếp từ Kali tới
`192.168.252.20`. Không rewrite destination MAC sang Ubuntu trong live test.
Ubuntu phải nhìn thấy unicast Kali ↔ Windows nhờ promiscuous mode của sensor
NIC trên VMnet1.

Ví dụ kiểm tra port:

```bash
nmap -n -Pn -sS -T3 --max-rate 100 -p 1-1024 192.168.252.20
```

Có thể tiếp tục chạy các test FTP, SSH, HTTP, SQLi, XSS hoặc slow HTTP mà không
restart sensor.
