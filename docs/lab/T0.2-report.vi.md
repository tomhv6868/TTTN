# Báo cáo T0.2 — Toolchain tái lập

## Phạm vi đã khóa

T0.2 cài toolchain build/inference trên Ubuntu 24.04 x86_64 nhưng không cấu hình runtime DPDK. NIC, default route, hugepages, IOMMU, VFIO và bootloader không bị thay đổi.

| Thành phần | Phiên bản/chính sách |
|---|---|
| DPDK | 25.11.2 LTS, build source đã khóa checksum |
| ONNX Runtime | 1.27.1 CPU Linux x64, binary release chính thức |
| C/C++ | GCC từ Ubuntu 24.04, smoke project bắt buộc C++20 |
| CMake | Tối thiểu 3.28 |
| Meson | Tối thiểu 0.57 |
| Ninja | Phiên bản từ Ubuntu repository |
| Python | 3.12.x |

Nguồn chính thức:

- DPDK download: <https://core.dpdk.org/download/>
- DPDK system requirements: <https://doc.dpdk.org/guides-25.11/linux_gsg/sys_reqs.html>
- ONNX Runtime v1.27.1: <https://github.com/microsoft/onnxruntime/releases/tag/v1.27.1>
- ONNX Runtime C++: <https://onnxruntime.ai/docs/get-started/with-cpp.html>

## Bố trí cài đặt

APT cài compiler và dependency hệ thống. DPDK và ONNX Runtime được cài dưới:

```text
~/.local/nids-toolchain/
├── dpdk/25.11.2/
├── onnxruntime/1.27.1/
└── env.sh
```

Không chạy installer bằng `sudo bash`. Script tự gọi `sudo` riêng cho `apt-get`; mọi source archive, build và prefix còn lại thuộc user hiện tại.

DPDK chỉ build các PMD cần cho lab/MVP: `net/intel/e1000`, `net/vmxnet3`, `net/pcap` và `net/ring`; chỉ build ứng dụng `test-pmd`, tắt DPDK unit tests và giới hạn mặc định hai build job.

ONNX Runtime release chứa file `pkg-config` trỏ về `/usr/local`, không phù hợp prefix cô lập. Installer tạo module `onnxruntime.pc` riêng trong prefix người dùng, trỏ đúng tới `include/` và `lib/` của archive.

## Quy trình chạy trên Ubuntu

Từ root workspace đã được chép/mount vào Ubuntu:

```bash
bash scripts/setup_toolchain_ubuntu.sh --dry-run
```

Đọc kỹ URL, checksum, package và install root. Sau đó cài:

```bash
set -o pipefail
bash scripts/setup_toolchain_ubuntu.sh --install \
  2>&1 | tee t0.2-install.log
```

Mở shell mới hoặc nạp environment rồi nghiệm thu:

```bash
source "$HOME/.local/nids-toolchain/env.sh"

set -o pipefail
bash scripts/setup_toolchain_ubuntu.sh --verify \
  --receipt toolchain-receipt.json \
  2>&1 | tee t0.2-verify.log
```

`--verify` thực hiện:

1. `bash -n` và ShellCheck cho installer.
2. CMake configure trong thư mục tạm sạch bằng Ninja.
3. Compile C++20 và link `libdpdk` + `libonnxruntime` qua `pkg-config`.
4. Chạy CTest; binary gọi `rte_version()`, `OrtGetApiBase()` và khởi tạo `Ort::Env`.
5. Xác minh `dpdk-testpmd` tồn tại và mọi shared-library dependency được `ldd` giải quyết, nhưng không khởi tạo EAL trước T0.3.
6. Ghi phiên bản APT thực tế, toolchain, artifact marker, runtime output và từng check vào receipt.

Không dùng `--force-receipt` trừ khi đã lưu/đối chiếu receipt cũ.

## Kiểm thử offline trong workspace

Các test này kiểm tra lock, checksum cố định, receipt schema, guard an toàn và cấu hình smoke project; chúng không giả lập việc cài APT hoặc link ELF Linux trên Windows:

```bash
python -B -m unittest discover -s tests -p "test_*.py" -v
python -B scripts/verify_toolchain.py validate \
  --input tests/fixtures/toolchain-receipt.sample.json \
  --lock config/toolchain.lock.json
```

## Rủi ro và giới hạn

- VM có 2 vCPU/2.86 GiB RAM nên build mặc định chỉ dùng hai job. Nếu kernel OOM, giữ nguyên artifact lỗi và báo cáo; không tự ý tăng RAM hoặc swap.
- APT packages không pin revision để Ubuntu vẫn nhận security updates. Revision thực tế được khóa hậu nghiệm trong receipt.
- ONNX Runtime 1.27.1 phải vượt dynamic-load và `Ort::Env` smoke test trước khi được chấp nhận.
- T0.2 chỉ chứng minh build/link/runtime userspace. Khả năng RX/TX, `e1000` PMD, hugepages và NIC binding thuộc T0.3.
- Receipt/log có hostname và đường dẫn user; không đưa artifact thô vào Git.

## Tiêu chí nghiệm thu

T0.2 chỉ sẵn sàng để người dùng chọn `Chấp nhận` khi:

1. `--install` hoàn tất trên Ubuntu 24.04.4 mà không đổi network. **Đạt.**
2. `--verify` trả mã 0 và CTest đạt. **Đạt: 1/1 test.**
3. Receipt có `status: passed`, DPDK `25.11.2`, ONNX Runtime `1.27.1`, Python `3.12.x` và mọi check đều `passed`. **Đạt: 37/37 check.**
4. Install log, verify rerun log và receipt rerun được lưu kèm SHA-256 để đối soát. **Đạt.**

Người dùng đã chọn `Chấp nhận` sau khi kiểm tra receipt và log rerun. T0.2 được đóng; T0.3 chỉ bắt đầu sau một cổng xác nhận riêng về thay đổi NIC, hugepages, IOMMU/VFIO và tiêu chí smoke test.
